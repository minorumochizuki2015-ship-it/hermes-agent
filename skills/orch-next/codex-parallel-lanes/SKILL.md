# Codex Parallel Lanes Skill

Preserve the public skill identity while routing all new exploration, implementation, and review lanes through Hermes.

## Full-fidelity train topology override

Marker: `INC191_FABLE5_FULL_FIDELITY_CONSUMER_ADOPTION_V1`.

Conditional-audit, cost, and deterministic-remainder optimizations cannot
override an admitted MK734/MK735 design without one allowed narrowing reason
and an equivalent replacement. For every repeated user-first-detection,
critical shared-runtime, cross-repository, lifecycle, or
first-natural-acceptance train, preserve:

- `AG-01`: exactly one controller and findings-union synthesizer;
- `AG-02`: bounded implementation writers with isolated, disjoint ownership;
- `AG-03`: one independent causal challenger for the whole train; the
  controller cannot suppress it because the controller's blind spot is itself
  in scope;
- `AG-04`: one continuously owned serial integrator for atomic content-return
  consumption;
- `AG-05`: acceptance exercised separately from every implementation writer;
- `AG-06`: sanitized train-close learning and later comparable-case capture.

Mechanical literals, exact pins, unchanged waits, and fully named one-point
remainders stay with the current owner and do not require a new paid lane.
`NO_ADDED_VALUE` is a valid typed challenger return for a duplicate,
agreement-only, status-only, or non-decision-changing question. These rules tune
process instantiation; they do not delete the six-role contract. Findings are
combined as a union, never a vote.

Every admitted bundle maps its stable IDs to exact lane questions and exactly
one allowed disposition: `implemented`, `already_implemented_verified`,
`active_owner`, `repo_fact_contradiction`, or
`protected_authority_blocker`. At least one lane or the controller must return
a `content_implementation_return` binding stable ID, changed or verified path,
behavioral delta, checks, rollback, and nonclaims. Intake, ledger, or topology
text without content fails `BLOCKED_FOR_FABLE_CONTENT_RETURN_MISSING`.

Narrowing requires a repo-fact contradiction, protected boundary, verified
duplicate, or concrete implementation hazard plus an equivalent replacement.
Cost may tune model, effort, and checkpoint, but cannot delete architecture,
challenge, integration, acceptance, or learning before natural evidence. Total
cost includes tokens/context, wall clock, review, rework, coordination,
recurrence, user correction, manual relay, capability delay, and
discarded-provider work. Missing usage is `UNKNOWN`, never zero.
`support_work_progress_credit=0` is not permission to remove causal prevention.
Keep `observed_effective_prevention=false` until a later comparable natural
case prevents the same correction before the user detects it.

## M-04 first-failing-seam union

Marker: `FABLE5_M04_EARLIEST_USER_JOURNEY_SEAM_WINS`.

Each admitted panoramic lane returns exactly one `first_failing_seam`, its
normal-user journey position, the current observable failure, and the CHK row
that would falsify it. The controller consumes the UNION of disjoint seams,
never a vote, and selects the earliest failing seam on the normal-user journey
as the first train. A deeper or more technically interesting seam cannot
displace it. Downstream burdens must state how they inherit from that selected
seam.

`NF-M04` rejects a first train without a normal-user-observable CHK row, or one
that skips an earlier failing seam, with
`BLOCKED_FOR_FABLE5_NF_M04_FIRST_TRAIN_NOT_EARLIEST_OBSERVABLE_SEAM`. This is a
work-selection Claim Check, not an Authority Gate.

This is a self-contained Hermes runtime contract. It does not create another
plugin, installer, bundle, configuration, schema, queue, or control family.

## Provider and surface capability contract

The selected provider and execution surface are one exact route. The existing
Hermes-native route remains the default for Hermes work; an explicit provider
selection is not a failure fallback:

- `hermes_native` + `delegate_task`: use Hermes `delegate_task`, consume its
  typed terminal result, and keep the one-writer/worktree contract.
- `codex_luna` + `direct_codex_exec`: use
  `scripts/dispatch_provider.py` for a headless direct `codex exec` with
  `-m gpt-5.6-luna`, an effort derived from the required work class,
  `-a never`, `danger-full-access`, and the exact resolved worktree.
  `deterministic_mechanical` binds Luna High; `precision_difficult` binds Luna
  Max and adds `-c service_tier=fast` to the actual child argv. Fast is not
  added for High. Runtime service tier remains `UNKNOWN` without a native
  Codex receipt, and Stop auto review is never claimed runtime-bound without
  an executable binding. Missing capability returns a typed unavailable result
  and never substitutes Sol or Terra.
- `codex_plugin_cc` + `codex_plugin_cc`: return a typed Claude bridge/job-
  control handoff. This source slice does not install, qualify, or invoke the
  bridge.

Codex.app is optional visibility/manual takeover or exact-session resume only;
it is never a scheduler, required runtime, or provider substitution. Every
route emits a sanitized requested/advertised/actual identity and result
receipt bound to job, thread, session, cwd/worktree, approval, sandbox,
terminal class, and result consumption. Empty or `UNKNOWN` output is typed
failure. Terminal output is bounded and sanitized, and `result_consumed=false`
until an actual consumer acknowledgment matches the result digest. The caller
selected executable is ignored: the admitted local Codex path, mode, size, and
SHA-256 must verify before launch, and arbitrary child text cannot establish
runtime identity. Exact resume compares the requested and native actual
session IDs. Ordinary writers use one owner-private durable lease and an
atomic lock family: worktrees, overlapping write sets, and shared runtimes may
not overlap; cohorts are capped at four and a fifth is rejected. Stop
auto-review is `false` by default and is not enabled by this skill.

- Read the active repository instructions and exact cwd, worktree, branch,

  credentials, private payloads, or provider payloads.

## Procedure

1. Restate the normal-user capability this operation will make possible and
   the evidence layer it can actually establish.
2. Load `references/delegate-task-contract.json` with `read_file`. Bind the
   exact task target, controller role `orchestrator`, worker role `leaf`,
   fixed `target_revision`, bounded `timeout_seconds`, read manifest, disjoint
   write manifest, and return contract before calling `delegate_task`.
3. Encode the target, read/write manifests, exact ownership, and return shape
   into `goal` and `context`. These are prompt constraints, not capability
   enforcement. A writer still requires an isolated worktree and external
   exactly-one-writer coordination; do not claim `delegate_task` enforces its
   write manifest.
4. Dispatch through `delegate_task` batch mode, with each task item carrying
   its `goal`, `context`, role, fixed `target_revision`, and bounded
   `timeout_seconds`. Consume exactly one terminal class:
   `completed`, `blocked`, `intentional_stop`, or `crash`. Do not infer success
   from an ended turn or from source presence.
5. For an ended session, use a registered resume surface (`/resume` in the
   gateway or `hermes --resume` in the CLI), then at most one `delegate_task`
   atomic successor. `session.reconnect` is not registered in this source; if
   reconnect is required, return `hermes_reconnect_unavailable` with
   `launch=false`. Preserve exactly one writer and never use the user as a
   packet/session relay.
6. Use the exact provider/surface route above. Use isolated worktrees,
   disjoint writes, one controller, bounded writer count, and atomic return
   integration. Never launch a different provider as a fallback harness.
7. Use native Hermes tools such as `read_file`, `search_files`, `terminal`,
   `patch`, `delegate_task`, `cronjob`, or `vision_analyze` only when
   they are available and necessary for this skill.
8. Keep source implementation, integration, installed adoption, fresh-session
   selection, runtime reachability, exercised behavior, user acceptance,
   effectiveness, and final completion separate.
9. Return the capability delta, blocker delta, exact owner and write set,
   checks run, rollback, next Hermes action, and precise non-claims.

## Failure behavior

- `hermes_runtime_unavailable`: the required Hermes operational surface is
  unavailable for a Hermes-native route; return `launch=false` and do not
  substitute another provider. An explicit Luna route has its own typed
  executable-availability result.
- `maestro_authority_unavailable`: the required protected-decision input is
  absent, stale, invalid, or unbound; return `launch=false`.
- `protected_transition_denied`: the typed authority result denies the exact
  transition; return `launch=false` and continue only disjoint safe work.
- `operation_scope_conflict`: another writer owns the same worktree, write
  set, or shared runtime; return `launch=false`.

Do not retry unchanged protected failures, manufacture work to fill a cohort,
or use the user as a manual task/session router.
