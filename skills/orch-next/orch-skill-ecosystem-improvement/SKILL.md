# Orch Skill Ecosystem Improvement Skill

Convert repeated skill misses into the smallest useful contract, fixture, or lifecycle correction.

## Full-role evidence before cost optimization

Marker: `INC191_FABLE5_FULL_FIDELITY_CONSUMER_ADOPTION_V1`.

For an admitted MK734/MK735 architecture, collect natural evidence with the
full `AG-01` through `AG-06` contract before proposing role deletion or
architectural narrowing. Model, effort, checkpoint, and deterministic-remainder
routing may be tuned immediately within existing authority, but projected cost
alone cannot remove architecture, premise challenge, counterhypothesis search,
independent challenge, integration ownership, acceptance separation, or
train-close learning. The controller cannot suppress `AG-03` for its own blind
spot.

The full contract is `AG-01` one controller/union synthesizer, `AG-02` bounded
disjoint writers, `AG-03` an independent causal challenger, `AG-04` an always-
owned serial integrator, `AG-05` acceptance separate from the writer, and
`AG-06` sanitized train-close learning and comparable-case capture.

Accepted-task cost records include tokens/context, wall-clock-to-first-delta,
wall-clock-to-accepted-result, review time, rework, coordination, recurrence,
user correction, manual relay, capability delay, discarded-provider work,
first-pass acceptance, retries, and escaped defects. Unknown or unexercised
values remain `UNKNOWN`, never zero. One incident, one task, or a lower price
cannot establish a default, superiority, role-deletion rule, or architectural
narrowing. If no new anomaly or comparable signal exists, `AG-06` records
sanitized deterministic telemetry and returns `NO_ADDED_VALUE` before a learner
model is launched.

Every learning candidate retains its originating stable ID and one of
`implemented`, `already_implemented_verified`, `active_owner`,
`repo_fact_contradiction`, or `protected_authority_blocker`. Require at least
one `content_implementation_return` before claiming consumer adoption; an
intake, ledger, report, or validator-only return fails
`BLOCKED_FOR_FABLE_CONTENT_RETURN_MISSING`. Narrow only for a repo-fact
contradiction, protected boundary, verified duplicate, or concrete
implementation hazard with an equivalent replacement.

`support_work_progress_credit=0` denies direct product-progress credit and is
not permission to delete a causal prevention dependency. Keep
`observed_effective_prevention=false` until a later comparable natural task
changes action before the user supplies the correction.

## M-10 two-failure acceptance replan

Marker: `FABLE5_M10_TWO_FAILURE_ACCEPTANCE_REPLAN`.

An explicit user correction changes the premise. Two failed attempts against
the same acceptance predicate, a 70-percent cost checkpoint without first
material delta, or evidence that the fixed decision is impossible forces
`STOP_AND_REPLAN` or an exact blocker. A silent third unchanged attempt is
forbidden. `NF-M10` returns
`BLOCKED_FOR_FABLE5_NF_M10_SILENT_THIRD_ACCEPTANCE_ATTEMPT`; another attempt is
admissible only after an intervening user decision or a genuinely changed
predicate or causal hypothesis.

## M-12 threshold provenance

Marker: `FABLE5_M12_THRESHOLD_PROVENANCE_REQUIRED`.

Every numeric threshold carries `threshold_provenance=measured` with referenced
natural observation rows, or
`threshold_provenance=a_priori_calibration_pending`. A threshold change always
carries the observation rows that caused it; repetition does not turn an
a-priori value into a measured value. The first 10 real accepted-task rows
trigger a calibration review, while MK749 retains quantitative promotion
ownership and its existing 12-task cohort.

`NF-M12` rejects a threshold-change claim with missing observation rows or
provenance using `BLOCKED_FOR_FABLE5_NF_M12_THRESHOLD_PROVENANCE_MISSING`. It
does not block product work.

This is a self-contained Hermes runtime contract. It does not create another
plugin, installer, bundle, configuration, schema, queue, or control family.

## Maestro authority boundary

Hermes owns this operation. When it reaches a protected transition or
claim-sensitive decision, consume the current versioned Maestro authority
bundle and its typed validator result. If that authority input is unavailable,
return `maestro_authority_unavailable` for the protected decision while
continuing disjoint safe work. Maestro is never an execution fallback.

Authority consumption remains an integration dependency. This source skill
does not claim that an authority adapter or validator executed. Until the
integration surface supplies a current, target-bound typed result, every
authority-required operation returns `maestro_authority_unavailable` with
`launch=false`.

## When to use

Use when the current ORCH-Next goal directly needs this capability. Do not
select it for a similarly named authority-only decision or for evidence work
that cannot change the current implementation or user outcome.

## Prerequisites

- Read the active repository instructions and exact cwd, worktree, branch,
  revision, dirty state, goal, owner, and write boundary.
- Use current repo-local source as truth. Treat historical packets and external
  memory as advisory unless the active authority index cites them.
- Preserve one writer per worktree or durable record. Use separate worktrees
  and disjoint writes for parallel workers.
- Never persist raw prompts, hidden reasoning, terminal logs, secrets,
  credentials, private payloads, or provider payloads.

## Procedure

1. Restate the normal-user capability this operation will make possible and
   the evidence layer it can actually establish.
2. Measure user corrections and recurrence; do not add a permanent control family from one incident.
3. Use native Hermes tools such as `read_file`, `search_files`, `terminal`,
   `patch`, `delegate_task`, `cronjob`, or `vision_analyze` only when
   they are available and necessary for this skill.
4. Keep source implementation, integration, installed adoption, fresh-session
   selection, runtime reachability, exercised behavior, user acceptance,
   effectiveness, and final completion separate.
5. Return the capability delta, blocker delta, exact owner and write set,
   checks run, rollback, next Hermes action, and precise non-claims.

## Failure behavior

- `hermes_runtime_unavailable`: the required Hermes operational surface is
  unavailable; return `launch=false` and do not substitute Maestro or Codex
  execution.
- `maestro_authority_unavailable`: the required protected-decision input is
  absent, stale, invalid, or unbound; return `launch=false`.
- `protected_transition_denied`: the typed authority result denies the exact
  transition; return `launch=false` and continue only disjoint safe work.
- `operation_scope_conflict`: another writer owns the same worktree, write
  set, or shared runtime; return `launch=false`.

Do not retry unchanged protected failures, manufacture work to fill a cohort,
or use the user as a manual task/session router.

## Verification

Verify the requested behavioral delta through the repository-prescribed checks
and, where applicable, the normal Hermes operation. A local document, source
PASS, test PASS, audit, or installed file never proves a higher evidence layer.
